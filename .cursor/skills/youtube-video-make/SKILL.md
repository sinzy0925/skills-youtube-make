# YouTube動画素材作成

殴り書きメモ、または **Cursor の会話ログ（`*.jsonl`）** から、Googleスライドに貼れる素材（構成・テキスト・ナレーション・画像）を順序立てて作成する。

**スキルの範囲**: コンテンツ生成と `upload.json` の出力まで。Googleスライドへの配置は `scripts/upload_to_slides.py` で自動化。Vids・YouTube投稿は手動（手順を案内する）。

## 入力の種類

| 入力 | 最初にやること |
|------|----------------|
| 殴り書きメモ・要点テキスト | Phase 0（パラメータ確認）へ |
| `*.jsonl`（Cursor 会話ログ） | **Phase 0S（要約）を必ず先に実行** → 承認後に Phase 0 |

jsonl を受け取ったら、全文をコンテキストに載せたまま構成作業へ進まない。必ず要約メモに落としてから本編に入る。

## デフォルト値

ユーザーが指定していない場合、以下を適用する（**形式・長さ・画像スタイル・確認ポイントは推測しない**）:

| 項目 | デフォルト |
|------|-----------|
| 言語 | 日本語 |
| 画面比率 | 16:9（YouTube想定） |
| トーン | カジュアルでわかりやすい |
| 想定視聴者 | 一般・初心者（メモの内容から読み取れる場合はそれに合わせる） |

## Phase 0S: 会話ログ要約（jsonl 入力時のみ・必須）

入力が `*.jsonl`（または「この会話ログを元に動画を」）のとき、**Phase 0 より前に**実行する。

### 目的

巨大・ノイズ多めの会話ログを、動画用の **殴り書きメモ相当** に圧縮する。以降の Phase は要約メモだけを正本にする。

### 手順

1. 出力先 `{slug}` が未確定なら、ログのテーマから仮 slug を決めフォルダを作る（例: `threads-api-intro`）
2. jsonl は可能なら **シェルで分割読み**（巨大ファイルをチャットに全部貼らない）
3. 次を抽出して `source-notes.md` を作成する:

```markdown
# 動画用メモ（会話ログ要約）

## テーマ
{何のアプリ／何の手順か}

## ゴール
{視聴者ができるようになること}

## 前提
{アカウント、ツール、環境}

## 手順（時系列）
1. ...
2. ...

## ハマりどころ・注意点
- ...

## 使ったコマンド / API / 画面（重要だけ）
- ...

## 動画で省略してよいこと
- ...

## 元ログ
- ファイル: {jsonl のパスまたは ID}
- 要約日: {日付}
```

4. **秘密情報は書かない**（アクセストークン、パスワード、`.env` の値、個人メールの乱用はマスク。User ID など動画に不要な識別子は省略可）
5. ユーザーに要約を提示し、**承認または修正**を待つ
6. 承認後、`source-notes.md` を殴り書きメモとして Phase 0 へ進む

### 確認ポイントとの関係

- jsonl 入力時は、確認ポイント A〜D に入る前に **要約の承認が追加で必須**
- 要約未承認のまま Phase 1（構成）に進まない

### 通常メモ入力のとき

Phase 0S はスキップ。ユーザーメモをそのまま Phase 0 の入力にする。

## Phase 0: パラメータ確認（必須）

殴り書きメモ（または Phase 0S で承認済みの `source-notes.md`）を受け取ったら、**作業を開始する前に**未指定項目を確認する。

### 必ず確認する4項目（未指定なら質問、推測しない）

1. **形式**: ぱらぱらマンガ型 / プレゼン型
2. **長さ・枚数の目安**: 例「3分・8枚」「5分・12枚」「内容に合わせて提案して」
3. **画像スタイル**: 例「フラットイラスト」「アニメ風」「シンプルな図解」「水彩風」
4. **確認ポイント**: どの段階で止めて承認するか
   - A: 構成案のみ
   - B: 構成＋確定テキストまで
   - C: 構成＋テキスト＋ナレーションまで
   - D: 全部自動（画像まで一気に）

### 形式の判定ルール

以下が**明示されているときのみ**質問をスキップする:

- マンガ型: 「マンガ型」「ぱらぱらマンガ」「コマ割り」「画像だけ」「コマ」
- プレゼン型: 「プレゼン型」「スライド」「説明＋画像」「資料形式」「プレゼン資料」

**メモの内容がストーリー調でも解説調でも、形式指定がなければ必ず聞く。**

### 質問の出し方

未指定項目が複数ある場合は、**1つのメッセージにまとめて質問**する。回答を得てから Phase 1 へ進む。

確認後、`brief.md` にパラメータを記録する（形式・枚数・スタイル・確認ポイント・トーン等）。

## ワークスペースと出力先

**動画1本＝1フォルダ＝1チャット** を推奨。成果物は**スキルリポの外**に出す。

### 出力先のルール

| ワークスペース | 出力先（デフォルト） |
|---------------|---------------------|
| `skills-youtube-make`（このリポ） | `../youtube-videos/{slug}/` |
| 動画専用フォルダ（`youtube-videos/{slug}/`） | ワークスペースルート（`.`） |

- `{slug}` はテーマの短い英数字（例: `cursor-intro`）。Phase 0 で確定し `brief.md` に記録する
- ユーザーが出力先を指定した場合はそれを優先する
- **スキルリポ内の `output/` には書かない**（リポが肥大化しトークン消費の原因になる）
- 出力先フォルダが無ければ作成する

`brief.md` に必ず記録:

```markdown
## 出力先
../youtube-videos/cursor-intro/
```

### 成果物の一覧（出力先フォルダ内）

```
{youtube-videos/{slug}/ または ./}
├── source-notes.md   # jsonl 入力時のみ（要約メモ・以降の正本）
├── brief.md
├── structure.md
├── content.md
├── narrations.md
├── upload.json
├── youtube-meta.md
├── images/
│   ├── thumbnail.png  # 必須・先頭サムネ（YouTubeサムネ兼用）
│   ├── slide-01.png   # プレゼン型（本編）
│   └── scene-01.png   # マンガ型（本編）
├── slides-result.json  # アップロード後
└── manual-steps.md
```

### 動画専用フォルダで作業している場合

ワークスペースが `youtube-videos/{slug}/` のときはルート（`.`）に直接出力。アップロードはターミナルで実行（エージェントが実行する必要はない）。

### スキルリポジトリで作業している場合

`../youtube-videos/{slug}/` に出力する。完了時に出力先パスをユーザーに伝え、必要ならそのフォルダを Cursor で開き直すよう案内する。

## Phase 1: 構成案

メモを分析し、`structure.md` を作成する。

### サムネスライド（必須・先頭・本編と同時進行）

**すべての動画で、本編の前にサムネスライドを1枚置く。**  
枚数指定は「本編の枚数」として扱い、合計は **本編＋1（サムネ）** になる。

**重要（後付け禁止）:** サムネは「本編が終わってから足す」ものではない。  
構成・本文・ナレーション・画像・`upload.json`・Drive アップロード・スライド投入まで、**本編と同じ Phase でまとめて進める。**

| 項目 | ルール |
|------|--------|
| 位置 | 構成・`upload.json`・Googleスライドの **先頭（index 1）** |
| 種別 | `thumbnail` |
| 画像 | `images/thumbnail.png`（16:9） |
| テキスト | YouTubeサムネ兼用のため **画像内に大きなタイトル文字を入れてよい**（本編画像は従来どおり文字なし） |
| ナレーション | 短いフック（目安 8〜15秒）。挨拶＋動画の一言要約 |
| スライド上の箇条書き | 最小限 or 空（視覚は画像が主役） |

Phase ごとの扱い:

| Phase | サムネの扱い |
|-------|-------------|
| 1 構成 | 一覧の **#1 に必ずサムネ行**を入れる |
| 3 コンテンツ | `content.md` の先頭セクションをサムネにする |
| 4 ナレーション | 本編と同時にサムネ台本を書く |
| 5 画像 | `thumbnail.png` を **本編画像と同じバッチで生成**する |
| 6 パッケージ | `upload.json` の `slides[0]` を最初からサムネにする |
| 6.5 アップロード | Drive に `thumbnail.png` も含めて上げ、**一括投入**（`--prepend` は使わない） |

構成表の1行目例:

| # | 種別 | タイトル | 要点 |
|---|------|---------|------|
| 1 | サムネ | {動画タイトルを大きく} | YouTubeサムネ兼用・短い導入ナレーション |

### プレゼン型の構成テンプレート

```markdown
# 構成案: {タイトル}

## 概要
{1-2文で動画の主旨}

## スライド一覧
| # | 種別 | タイトル | 要点 |
|---|------|---------|------|
| 1 | サムネ | {動画タイトル} | YouTubeサムネ兼用 |
| 2 | オープニング | {フック・問いかけ} | |
| 3 | 本編 | | |
| ... | | | |
| N | エンディング | まとめ＋CTA | |
```

- 1枚目: **サムネ**（必須）
- 2枚目: 結論・問いかけ・フック（オープニング）
- 最終枚: まとめ＋次のアクション（チャンネル登録など）
- 本編1枚あたり箇条書き **3行以内**（指定があれば従う）

### マンガ型の構成テンプレート

```markdown
# 構成案: {タイトル}

## 概要
{1-2文で動画の主旨}

## シーン一覧
| # | 場面 | ナレーション概要 | 画像で見せること |
|---|------|-----------------|-----------------|
| 1 | サムネ | 短いフック | YouTubeサムネ（タイトル文字入り可） |
| 2 | オープニング | | |
| 3 | | | |
| ... | | | |
| N | エンディング | | |
```

- 1コマ目は **サムネ必須**（`images/thumbnail.png`）
- 本編コマは1コマ＝1場面。情報を詰め込みすぎない
- 本編の画像内の文字・吹き出しは**デフォルトで入れない**（ナレーションで説明）。ユーザーが「セリフ入り」と指定した場合のみ入れる
- **サムネだけ例外**: タイトルなど大きな文字を画像に入れてよい

### 確認ポイント A 以上 → ここで停止

ユーザーに構成案を提示し、承認または修正指示を待つ。修正は `structure.md` に反映してから次へ。

## Phase 2: 微修正

ユーザーのフィードバックを `structure.md` に反映する。承認が得られるまで Phase 3 に進まない。

## Phase 3: 確定コンテンツ

`content.md` を作成する。詳細テンプレートは [reference.md](reference.md) を参照。

### プレゼン型 `content.md`

各スライドに: タイトル、箇条書き、スピーカーノート（制作メモ）、画像の方向性

### マンガ型 `content.md`

各シーンに: 場面説明、ナレーション概要、画像プロンプト要素（人物・動作・背景・画風）

### 確認ポイント B 以上 → ここで停止

## Phase 4: ナレーション

`narrations.md` を作成する。

```markdown
# ナレーション台本

## スライド 1 / シーン 1
**目安時間**: 15秒
**台本**:
{読み上げテキスト}

---
（以下同様）
```

ルール:
- 指定トーン（デフォルト: カジュアルでわかりやすい）で統一
- スライド/シーンの表示テキストをそのまま読むのではなく、自然な話し言葉にする
- **サムネ（先頭）**: 8〜15秒。挨拶＋「今日は○○を解説します」程度のフック
- 1枚あたり目安: プレゼン型 15〜30秒、マンガ型 10〜20秒（長さ指定に合わせて調整）

### 確認ポイント C 以上 → ここで停止

## Phase 5: 画像生成

`images/` に画像を生成する。画像生成ツールが利用可能なら実行する。不可の場合は各画像の詳細プロンプトを `content.md` に追記し、ユーザーに生成を依頼する。

### 画像生成ルール

- **比率**: 16:9
- **スタイル**: Phase 0 で確定した画像スタイルを全枚で統一（サムネも同系統）
- **サムネ（必須）**: `images/thumbnail.png`。YouTubeサムネ兼用。**大きなタイトル文字を画像内に入れてよい**。視線を止める構図・余白・コントラストを意識
- **生成順**: `thumbnail.png` → 本編画像。**本編だけ先に完成させてサムネを後回しにしない**
- **マンガ型（本編）**: 1場面が伝わる構図。デフォルトで文字・吹き出しなし
- **プレゼン型（本編）**: 補助的な図解・イラスト。スライドのテキストを画像に入れない（テキストはGoogleスライド側で入れる）
- **キャラ一貫性（マンガ型）**: 同一人物が登場する場合、各プロンプトに共通のキャラ描写を含める（`brief.md` に記録して再利用）

### ファイル名

- **サムネ（共通・必須）**: `thumbnail.png`（常に先頭）
- プレゼン型本編: `slide-01.png`, `slide-02.png`, ...
- マンガ型本編: `scene-01.png`, `scene-02.png`, ...

## Phase 6: 成果物パッケージ

1. `upload.json` を作成（**必須**）:
   - `content.md` + `narrations.md` + 画像パスを1ファイルに統合
   - **`slides[0]` は必ず `slide_type: "thumbnail"` / `image: "images/thumbnail.png"`**
   - スキーマは [reference.md](reference.md) の `upload.json` を参照
   - アップロードスクリプトはこの JSON だけを読む（Markdown は人間用）
   - サムネ無しの JSON は成果物として不完全（作り直す）

2. `youtube-meta.md` を作成:
   - タイトル案（3つ）
   - 説明文
   - タグ案
   - 想定視聴者メモ

3. `manual-steps.md` を作成（[reference.md](reference.md) の手順テンプレートを使用）

4. ユーザーに**出力先フルパス**と成果物一覧を報告し、アップロード方法を案内:

```
../youtube-videos/{slug}/   （スキルリポから実行時の例）
├── brief.md
├── structure.md
├── content.md
├── narrations.md
├── upload.json       ← スクリプト用
├── youtube-meta.md
├── images/（N枚）
└── manual-steps.md
```

## Phase 6.5: Googleスライドへアップロード

`upload.json` と `images/` が揃ったら、**ユーザーに次の手順を案内する**（エージェントが API を叩く必要はない。トークン節約）。

### なぜ Drive 経由が必要か

サービスアカウント（SA）は **Drive の保存容量が 0** のため、ローカル画像を直接 Drive に新規作成できない。  
成功パターンは次のとおり:

```
ローカル images/
  →【手動】共有 Drive フォルダへアップロード
  → upload_to_slides.py（SA がフォルダ内画像を参照してスライドへ配置）
```

設定の既定値: `config/drive_staging.json`

| 項目 | 値 |
|------|-----|
| 画像ステージングフォルダ | https://drive.google.com/drive/folders/1lBk5TQFmcA-Atygu0jV1NKGwT3o4kicB?usp=sharing |
| folder_id | `1lBk5TQFmcA-Atygu0jV1NKGwT3o4kicB` |

### ユーザーへの案内（この順で促す）

1. **空の Google スライドを用意**（未作成なら新規）  
   - SA `sheets-to-stockscode20@getstockdata05.iam.gserviceaccount.com` を **編集者** で共有  
   - プレゼン URL（または ID）を控える
2. **ローカル `images/` を Drive にアップロード**  
   - フォルダを開く: https://drive.google.com/drive/folders/1lBk5TQFmcA-Atygu0jV1NKGwT3o4kicB?usp=sharing  
   - **`thumbnail.png` を含む全画像**を一度にアップロード（同名は上書き）  
   - フォルダは SA に **閲覧者以上** で共有済みであること
3. **スクリプトを実行**（下記コマンド）  
   - **通常は一括投入のみ。** `--prepend`（サムネ後付け）は使わない

Phase 6 完了時の報告では、**「thumbnail.png を含む images/ を Drive へ上げてから、一括でコマンド実行」** と必ず書く。

### スキルリポジトリで作業した場合

```bash
pip install -r requirements.txt
python scripts/upload_to_slides.py ../youtube-videos/{slug} \
  --presentation-id "https://docs.google.com/presentation/d/PRESENTATION_ID/edit" \
  --image-folder-id "1lBk5TQFmcA-Atygu0jV1NKGwT3o4kicB"
```

### 動画専用フォルダで作業した場合

```bash
python <skills-youtube-make>/scripts/upload_to_slides.py . \
  --credentials <skills-youtube-make>/secrets/getstockdata05-service-account.json \
  --presentation-id "https://docs.google.com/presentation/d/PRESENTATION_ID/edit" \
  --image-folder-id "1lBk5TQFmcA-Atygu0jV1NKGwT3o4kicB"
```

- 認証: `secrets/getstockdata05-service-account.json`（サービスアカウント）
- `--image-folder-id` はフォルダ URL でも可（省略時は `config/drive_staging.json`）
- `--presentation-id` はスライド URL でも可（SA が新規作成できないため **既存デッキ必須**）
- 成功すると `slides-result.json` にプレゼン URL が記録される
- `--dry-run` で JSON とローカル画像の存在だけ検証可能（Drive アップロード前のチェック用）
- `--prepend` は **過去デッキへの緊急復旧用**。新規動画では案内しない

## Phase 7: 手動連携（ユーザー作業）

以下はユーザーが手動で行う（`manual-steps.md` に詳細を記載）:

1. 生成された Googleスライドを確認（Phase 6.5 で完了済み）
2. 動画に変換ボタン → Google Vids に連携
3. Vids で AI voiceover 生成 →「YouTubeに変換」

### 形式別の貼り付け方

| | プレゼン型 | マンガ型 |
|---|-----------|---------|
| テキスト | `content.md` のタイトル・箇条書きを各スライドに | 不要（または最小限） |
| 画像 | 右側または下部に配置 | 全面に配置 |
| ナレーション | Vids で `narrations.md` を参考に音声設定 | 同左 |

## 禁止事項

- 形式・長さ・画像スタイル・確認ポイントを推測で決めない
- 確認ポイントで指定された段階を飛ばして次に進まない
- ユーザーの承認前に画像生成を開始しない（確認ポイント D の場合を除く）
- Vids / YouTube の API や UI を自動操作しない（手順案内のみ）
- `upload.json` を省略しない（アップロードスクリプトの入力として必須）
- 動画専用フォルダで `output/` サブフォルダを作らない（ルートに直接出力）
- Phase 6.5 でエージェント自身が upload スクリプトを実行しない（案内のみ）
- Phase 6.5 では「thumbnail.png を含む images/ を Drive ステージングへ上げてから一括実行」を必ず案内する（SA 直アップロードは不可）
- **サムネを本編の後工程に回さない**（後から `--prepend` する運用を新規動画の標準にしない）
- `upload.json` にサムネが無い状態で Phase 6 完了と報告しない
- **jsonl 入力時に Phase 0S（要約）を飛ばさない**
- **要約未承認のまま構成・画像に進まない**
- jsonl 全文を Phase 1 以降の正本にしない（正本は `source-notes.md`）
- 要約や成果物にアクセストークン・パスワード等の秘密情報を残さない
